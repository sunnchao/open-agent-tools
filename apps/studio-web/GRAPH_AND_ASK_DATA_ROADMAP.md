# 图谱与问数能力对标及补全路线

> 调研日期：2026-09-18。竞品能力以公开产品页和官方文档为准；本表用于确定产品差距，不代表采购结论。

## 1. 当前基线

### 知识图谱

当前已具备文档实体/关系抽取、来源级同步与对账、GraphRAG 子图检索、2 跳展开、实体属性查看和关系类型统计。本轮补上了多重关系错峰曲线、双向边分离、四向端口、边选中和关系详情。

### 问数

当前支持配置多个 MySQL Schema 源、加密保存连接串、默认源与运行时切换、按源隔离 catalog/图谱缓存、表范围过滤，以及通用/oneapi 语义模板。问数链路具备基于 GraphRAG 的选表、推断引用关系、分档 schema 注入、当前源表边界校验、只读 SQL 护栏、澄清追问、结果预览和引用链高亮。

## 3. 连线实现方案

本轮采用共享的 `RelationEdge`，知识图谱和 Schema 图只负责提供关系数据与状态，路径计算统一处理：

1. 以无向节点对分组，为同一对节点的多条边分配对称车道。
2. 反向边将局部偏移翻转，保证 `A -> B` 和 `B -> A` 不会落在同一物理曲线上。
3. 根据节点相对位置选择上、右、下、左端口，减少边穿过节点和折返。
4. 使用二次曲线连接，标签落在曲线中点；保留 24-26 px 的透明命中区，视觉线宽与点击难度解耦。
5. 关系边只承担渲染；高亮、选中、权限等业务状态由各工作区注入，避免两套画布继续分叉。

下一阶段不建议立即引入复杂自动布线。先用“布局切换 + 稠密度阈值 + 聚类/折叠”控制规模；超过约 100 个可见节点后，再评估 WebGL 渲染与 edge bundling。

## 4. 建议路线图

### P0：从演示到可用

| 能力              | 交付物                                                             | 验收标准                                           |
| ----------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 语义层            | 指标、维度、事实、业务术语、同义词、显式 join path；版本发布与回滚 | 典型问法不再依赖物理列名；错误 join 可在配置层修正 |
| Verified Query 库 | 问题、标准 SQL、期望列/口径、适用语义版本                          | 每次模型或语义层变更自动跑回归，并展示准确率变化   |
| 查询安全治理      | 登录态传递、表/列/行权限、超时、扫描量/行数限制、审计              | 生成 SQL 与直接查询遵守同一权限；拒绝原因可追踪    |
| 图谱证据链        | 关系来源文档、chunk、抽取方式、置信度和时间                        | 点击每条关系都能回答“依据是什么”                   |
| 图谱筛选          | 实体类型、关系类型、来源、时间、置信度组合筛选                     | 稠密子图可以在不重查数据的情况下快速降噪           |
| 统一运行记录      | 问题、改写、选表、语义版本、模型、SQL、耗时、结果状态              | 一次失败可完整复盘，不依赖服务日志拼接             |

## 5. 推荐的下一迭代

先做一个“可信问数”纵向切片，而不是同时铺开全部 P0：

1. 为 `users / logs / channels` 定义最小语义层，包含 5-8 个核心指标和显式关系。
2. 建立 30 条真实运营问法的 Verified Query 集，并接入 CI 回归。
3. 在结果区展示“问题解释、使用口径、来源表、SQL、语义版本”，增加反馈入口。
4. 图谱关系补 `sourceChunk / confidence / extractionMethod`，在关系详情中展示证据。
5. 以 20、100、500 节点三档数据做画布性能基线，再决定是否引入 WebGL 或边捆绑。

## 7. 商业化前置条件

多源配置解决了单库写死问题，但对外提供服务前仍必须完成以下平台能力：

1. 为 `schema_sources` 增加租户归属，并让列表、默认源、查询和图谱文件都按租户隔离。
2. 为管理 API 增加管理员鉴权；问数 API 根据用户角色校验可访问的数据源。
3. 生产环境将配置密钥托管到 KMS/Secret Manager，并建立密钥轮换流程。
4. 数据源账号强制只读，增加连接网络策略、查询并发、扫描量、超时和成本配额。
5. 采集与建图改为后台任务，记录版本、失败重试、Schema 漂移和审计事件。
6. 在连接器接口稳定后补 PostgreSQL、ClickHouse 与云数仓适配器。
